### M0 执行计划

目标：确认 StPageFlip（npm 包 `page-flip`）在 iPad Safari 上能满足阅读端要求，决定最终翻页方案。

1. **样本拆页脚本**：写 `backend/scripts/render_samples.py`（用 uv 管理依赖，pypdfium2 + Pillow），按 05 文档的参数把 `samples/*.pdf` 渲染成 WebP（长边 2048px、质量 80），输出到 `samples/rendered/{书名}/0000.webp…`，同时打印每本书的页数、判断出的横竖版、单页平均体积。这一步也顺带校准图片压缩参数。
2. **翻页原型**：在前端加一个临时路由 `/prototype/flip`，用 `page-flip` 加载上一步生成的图片；按 [阅读端排版规则](./02-reader.md#横竖版排版) 实现：竖版书横屏对开、封面单独一页，横版书始终单页。背景先套小剧场配色。
3. **在 iPad 上测试**：`npm run dev -- --host` 后，用同一局域网内的 iPad 打开 `http://<电脑IP>:5173/prototype/flip`。
4. **验证清单**（逐项记录结果）：
   - [ ] 卷页效果在 iPad Safari 上流畅、手势跟手
   - [ ] 30 页以上的绘本翻页不卡顿、内存不崩
   - [ ] 竖版书横屏对开、封面单独一页
   - [ ] 横版书能强制单页显示
   - [ ] 平板横竖屏切换后排版正确
   - [ ] 全屏 API 在 iPad Safari 上可用
5. **输出结论**：把验证结果和最终翻页方案写进 `05-tech-design.md` 第 3.2 节，并在 `decision-log.md` 记录（下一个编号 **D39**）。不达标时，给用户 2–3 个替代方案（其他库 / 自研 CSS 3D 翻页）并附推荐。
6. M0 原型代码是临时的：进入 M3 时按正式结构重写，删除 `/prototype` 路由。
