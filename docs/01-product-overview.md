# 产品概述

> 产品名：**萤火**（英文 Firefly Tales，D45；dance-page 仅为项目代号）· 状态：第一期需求已确认 · 最后更新 2026-09-28

## 一句话定位

一个 Web 端的儿童绘本阅读器：管理员上传绘本（PDF）并管理书架，孩子在平板上像翻真书一样阅读；后续演进为 AI Native 的"会说话、会动"的绘本。

## 使用范围与部署

- **自用 / 小范围使用**（自己家庭或少量亲友），不是面向公众的产品，不做商业化。
- **部署在公网云服务器上**，因此整个系统需要账户体系，未登录用户不能访问任何绘本内容。

## 用户角色与账户体系

| 角色 | 数量 | 账户来源 | 使用端 | 能做什么 |
| --- | --- | --- | --- | --- |
| **管理员（Admin）** | 仅 1 个 | 部署时通过服务器配置设置 | Admin 管理后台 | 上传绘本、管理书架、管理读者和邀请码、配置 AI、触发和管理 AI 生成 |
| **读者（Reader）** | 多个 | 使用管理员分发的**邀请码**注册 | 阅读端 | 只能浏览书架、阅读绘本，不能上传、删除、修改 |

- 不开放自由注册：没有邀请码无法成为读者。
- 两个角色使用两套独立界面，阅读端不暴露任何管理能力。
- 所有读者共用同一个书架，不做按读者分配绘本的权限。

## 设备与内容

- **阅读端主要设备：平板电脑。**
- **绘本方向不固定**：有横版也有竖版的 PDF，阅读端必须能正确适配两种版式。
- **绘本来源**：网上下载的 PDF。按"PDF 每一页 = 一个独立画面"处理，不考虑一页 PDF 中拼了两页（跨页拆分）的情况。
- **语言**：中文、英文。

## 存储与图片质量

- 服务器磁盘 **512GB**。
- 页面图片取清晰度与体积的**压缩甜点位**：长边约 2000px 的高清图，采用 WebP 等高压缩比格式，单页约 300–500KB，一本 30 页的绘本约 10–15MB。具体参数开发时实测校准。
- **保留原始 PDF**：以后调整图片参数或 AI 识别需要更高清的图时，可以从原文件重新生成。
- 容量估算：即使加上原 PDF 和后续 AI 视频（每页约 2–5MB），512GB 也足够存放上千本绘本，第一期无需为容量做额外设计。

## 版本规划

| 阶段 | 目标 | 核心能力 |
| --- | --- | --- |
| **第一期（MVP）** | 把"上传 → 书架 → 翻页阅读"跑通 | 账户与邀请码；Admin 上传 PDF、管理书架；阅读端网格书架、仿真翻页阅读。详见 [MVP 范围](./04-mvp-scope.md) |
| 后续：AI 朗读 | 绘本能"读出来" | AI 提取每页文字 → 管理员校对台词 → TTS 朗读 |
| 后续：AI 动画 | 绘本能"动起来" | 视频模型将每一页生成简单动画 |

第一期只做阅读，不做 AI 功能，但架构上要为 AI 能力预留位置（见下文"核心概念"）。

## 绘本状态

绘本有两个相互独立的状态维度：

**可见性**（第一期）

| 状态 | 含义 |
| --- | --- |
| **已上架** | 读者可以在书架上看到并阅读。PDF 上传并处理完成后默认为此状态 |
| **已下架** | 读者看不到，但数据保留，管理员可重新上架 |

**AI 状态**（AI 阶段启用）

| 状态 | 含义 |
| --- | --- |
| 未处理 | 只有页面图片，读者只能翻页阅读 |
| **Dance Ready!** | 已完成 AI 处理并经管理员确认，读者可使用朗读和动画 |

## AI 能力的总体原则

- **成本由管理员承担**：管理员在 Admin 后台配置 AI 服务。
- **按能力分别配置模型**：文字提取（OCR）、TTS、视频生成各自配置服务商、模型和 API Key。
- **一本书生成一次，所有读者共用**：AI 产物（台词、音频、视频）按书生成并保存，读者阅读时直接播放已生成的内容，读者端不会触发任何 AI 调用。
- **人工校对优先于生成**：先识别台词、管理员校对，再生成朗读音频，避免为错误文字付费。详见 [Admin 需求 - AI 生成流程](./03-admin.md#ai-生成流程)。
- API Key 只保存在服务端，不能下发到阅读端。
- 绘本页面会发送给第三方模型服务处理。

## 核心概念

后续所有 AI 能力（文字提取、朗读、动画）的处理单位都是**单页**，因此从第一期开始就把"页"作为一等实体设计：

```
Book（绘本）
 ├── 元信息：书名、封面、版式（横/竖）、语言（中/英）
 ├── 状态：可见性（上架/下架）、AI 状态（未处理 / Dance Ready!）
 └── Page（页）× N
      ├── 页面图片            ← 第一期：上传后由 PDF 渲染生成，用于阅读
      ├── 朗读台词            ← 后续：默认由 OCR 提取，管理员可修改；可为空（无字页）
      ├── 朗读音频            ← 后续：由"朗读台词"经 TTS 生成
      └── 页面动画视频        ← 后续：由页面图片经视频模型生成
```

这样第一期阅读时直接加载页面图片，不需要在浏览器里解析整个 PDF；后续的 AI 能力只是给每一页挂上新的产物，不需要改动书和页的结构。

> 注：这里是产品层面的概念模型；具体技术方案待技术设计阶段确认。
